# Telemetry Collection System

Система сбора телеметрии согласно ТЗ:

- **4 источника**, опрос раз в секунду.
- Каждый источник отдаёт **100–600 объектов** на тик (случайно), из каталога **до 1000 объектов**.
- Значения **скалярные** (int/float) и **булевы** (bool).
- **Валидация**: валидные значения → SQLite (`telemetry.db`), невалидные → лог-файл + таблица `invalid_log`.
- **20 трендов** (предопределённый набор) логируются в БД; для каждого тренда поддерживается
  **постоянное окно видимости 3600 элементов** (и в памяти, и в БД — старые записи удаляются).
- GUI нет. Запуск из консоли.

## Структура

```
telemetry_system/
├── main.py                 # точка входа
├── telemetry/
│   ├── __init__.py
│   ├── config.py           # настройки системы
│   ├── models.py           # модели данных
│   ├── sources.py          # источники (симулятор + базовый интерфейс)
│   ├── validator.py        # валидация значений
│   ├── storage.py          # слой SQLite
│   ├── trends.py           # журнал трендов с окном 3600
│   └── collector.py        # главный цикл сбора
└── tests/
    └── test_validator.py   # тесты валидатора
```

## Запуск

```bash
python main.py                 # бесконечный сбор (Ctrl+C для остановки)
python main.py --duration 60   # работать 60 секунд и выйти
```

Логи: `logs/telemetry.log`. База: `telemetry.db`.

## Проверка окна трендов

```python
from telemetry.storage import Storage
s = Storage("telemetry.db")
print(s.get_trend_window("TREND_01"))   # последние <= 3600 значений
```

## Замена симулятора на реальные источники

Реализуйте интерфейс `BaseSource` из `telemetry/sources.py`
(метод `read() -> list[TelemetryValue]`) и подайте свои источники в `Collector`.
